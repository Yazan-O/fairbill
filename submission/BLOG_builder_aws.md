# Agents for Humans: teaching an agent to read a hospital's price file

Every hospital in the United States has to publish the price of everything it does. The rule is [45 CFR 180.50](https://www.ecfr.gov/current/title-45/part-180). The file is public, free, and sitting on the hospital's own website right now.

Norman Regional Health System's file is 39,141,747 bytes and 151,439 lines. OU Health publishes a wide CSV with 467 columns through a vendor endpoint. These are not documents a person reads. They are documents a person gives up on.

That is the gap Fairbill closes. You photograph a hospital bill. It reads the photo, identifies the hospital, downloads that hospital's published file live, and puts the hospital's own posted price next to every line you were charged.

The interesting engineering is who is allowed to make a claim.

## Models propose, code decides

The obvious build is one agent with a price-lookup tool. Ask it to audit the bill, let it call the tool, let it write the finding. It works in a demo and it is not trustworthy, because the sentence "the hospital's own file says $269.40" was generated by a language model. So was the file line number. So was the citation.

Fairbill splits those roles. Three specialists run in parallel over the bill: a line matcher, a coding specialist, and a rights specialist. Each one proposes claims. A claim carries a kind, which bill lines, which codes, whether a human needs to judge it, and a confidence. That is all. No price, no file row, no citation. Evidence is named by code, not copied.

A deterministic Python validator then rebuilds every finding from scratch against the hospital's file. If it cannot re-derive the claim, the claim is dropped.

Here is the whole rule for duplicates, from `src/fairbill/audit.py`:

```python
if c.kind == "duplicate":
    if len(sel) != 2:
        return "a duplicate must name exactly two lines"
    a, b = sel
    if a.line_no == b.line_no:
        return "a duplicate must name two different lines"
    if not a.code or a.code != b.code or abs(a.charge - b.charge) > 0.005:
        return "the two lines do not carry the same code and the same charge"
    if not _same_date(a, b):
        return "the two lines are for different dates of service"
    row = _row_for_line(hospital_id, a.code, a.charge)
    if row is None:
        return f"code {a.code} has no row in the hospital file"
    return Finding(kind="duplicate", line_nos=nos, evidence=[_to_row(row)], basis=basis,
                   amount_at_stake=round(_price(b) or 0.0, 2), confidence=c.confidence,
                   summary=c.summary or f"{a.description} (code {a.code}) is billed twice on lines {nos[0]} and {nos[1]}.")
```

Every string this returns on failure is a reason a model got told no. Two lines with the same code but different dates of service are not a duplicate; they are two visits. A code with no row in the hospital's file cannot be cited against that hospital. The `evidence` field is filled by `_row_for_line`, which reads the file. The model never touches it.

This rule set did not arrive fully formed. A review harness fed the first version twelve forged claims and it accepted seven of them: cross-date duplicates, above-cash flags computed from gross charges on insured lines, two-component "unbundling", negative amounts at stake. Each of those is now a line in the validator.

## Graph, not Swarm

The three specialists have no reason to wait for each other. In Strands, `Graph` runs its nodes in parallel and `Swarm` does not, so the audit is a graph.

```python
b = GraphBuilder()
b.add_node(ContextNode(), "context")
for name in SPECIALISTS:
    b.add_node(SpecialistNode(name, collector), name)
    b.add_edge("context", name)
b.add_node(ValidatorNode(collector), "validator")
for name in SPECIALISTS:
    b.add_edge(name, "validator", condition=all_dependencies_complete(list(SPECIALISTS)))
b.set_entry_point("context")
b.set_node_timeout(120)
b.set_execution_timeout(300)
graph = b.build()
```

A context node fans out to three specialists. All three converge on one validator, gated by `all_dependencies_complete`, so the validator runs exactly once with everything in hand.

Each `SpecialistNode` subclasses `MultiAgentBase` and never raises. A specialist that fails retries on the fallback model and then returns an empty claim set. A bill audit that loses one specialist is a weaker audit. A bill audit that throws is a broken product.

That design also makes the fallback model safe. The primary model is Claude Sonnet 4.6 on Amazon Bedrock; the fallback is Claude Haiku 4.5, same region. Both pass through the same validator. A cheaper model cannot lower the evidence bar, because the evidence bar is not in the model.

## The guard is code, not a prompt

Fairbill drafts dispute letters about money. It must never move any. A Strands `InterventionHandler` sits in front of every tool call:

```python
class MoneyGuard(InterventionHandler):
    """Denies any tool call that would move money. Fails closed."""

    name = "fairbill_money_guard"
    on_error = "deny"

    def __init__(self, session_id: str = "guard", bill_id: str | None = None):
        self.session_id = session_id
        self.bill_id = bill_id
        self.calls: list[dict] = []

    def before_tool_call(self, event):
        tool_use = getattr(event, "tool_use", None) or {}
        name = tool_use.get("name", "")
        reason = screen(name, tool_use.get("input"))
        if reason:
            self.calls.append({"name": name, "status": "denied", "reason": reason})
            ledger.record(self.session_id, "guard_denial", reason, bill_id=self.bill_id,
                          evidence=[f"tool {name}"], undo=None, actor="guard")
            return Deny(reason=reason)
        return Proceed()
```

`screen` matches the tool name against payment verbs and the arguments against card-shaped digit runs, routing numbers, and CVV fields. `on_error = "deny"` is the important line: if the guard itself throws, the call is denied. A safety check that fails open is decoration.

There is a decoy `pay_bill` tool in the demo whose only purpose is to be refused on camera. Its execution counter has never left zero.

## Deskew before you prompt

The reader was where the project nearly died. A photograph of a printed page arrives rotated by two or three degrees. On a wide statement table, that shifts the right-hand money columns by a full row height, and the model confidently attaches the wrong amount to the wrong line.

The fix is not a better prompt. It is OpenCV finding the page quad and warping it flat before the model sees anything. That undoes the geometry only; no pixel content is invented. The reader then makes two passes: a verbatim transcription, then a structured-output pass into the bill schema.

Deskew took the reader bench from 3 of 6 to 6 of 6 (`evals/READER_ABLATION.md` in the repo).

## Shipping it: AgentCore Runtime

The audit engine needs to serve HTTP, stream events to a phone as each step finishes, and stay warm between calls. AgentCore Runtime's direct-code mode fits: hand it a zip, it runs it.

The entrypoint is a `BedrockAgentCoreApp` with one `@app.entrypoint` handler serving `/ping` and `/invocations`. The deployment is Python 3.13 on ARM64, pushed with boto3 `create_agent_runtime` and `update_agent_runtime` from `deploy/deploy_runtime.py`.

A Lambda Function URL in `RESPONSE_STREAM` mode sits in front. It serves the static page on `GET /` and forwards audit calls to `InvokeAgentRuntime`. Each pipeline step streams back as a server-sent event, so the phone shows progress through the 238 s run.

One URL. One QR code. The whole demo.

## The bench, including the bill with nothing wrong

There is no public corpus of real patient bills, so the bench is six statements built from real price-file rows with invented patients, printed and photographed. Ground truth is committed. Five carry a planted error. The sixth is clean.

| suite | what it runs | planted found | false flags | reader |
| --- | --- | --- | --- | --- |
| truth | audits the bill as printed | 5 of 5 | 0 | not used |
| e2e | reads the photo, then audits what it read | 5 of 5 | 0 | 6 of 6 exact |

Zero false flags includes zero on the clean bill. That case is in the demo on purpose. An auditor that always finds something is not an auditor, and a patient who gets told their correct bill is wrong will not come back.
