## A. Core module `src/fairbill/decisions.py` (+ `letters.py`, `ledger.py`, `guard.py`, `fetch.py`)

### A1. Schema additions (`schema.py`, append only)
```
Option(id: str, label: str, consequence: str)            # ids: "dispute" | "itemized" | "drop" | "ask_provider" | "pay_in_network"
DecisionCard(bill_id, situation: str (max 2 sentences), options: list[Option] (2..3), default_option: str, deadline: date, deadline_reason: str, evidence_url: str, evidence_lines: list[int], amount_at_stake: float, basis: str, needs_user_judgment: bool, clean: bool)
Letter(bill_id, kind: "dispute" | "itemized_request" | "nsa_complaint", to_name, to_address, from_name, re_line, body: str, citations: list[str], footer: str)
LedgerEntry(id, ts (ISO, UTC), session_id, bill_id, action: str, why: str, evidence: list[str], undo: str | None, undone: bool = False, final_after: str | None (ISO; veto window), actor: "agent" | "user" | "guard")
FetchReport(hospital_id, url, status: "live" | "fixture" | "live_partial", bytes: int, total_bytes: int | None, seconds: float, sha256: str | None, matched_fixture: bool | None, note: str)
```

### A2. Decision Card (`decisions.py`): `build_card(bill: Bill, result: AuditResult, bill_id: str, today: date) -> DecisionCard`. Deterministic Python, no model call. Rules:
- clean (no findings): situation "This bill matches the hospital's published prices line by line. Nothing to dispute."; options [drop ("Close the case", "Nothing is sent; the check is logged")] only; default drop; deadline = statement due date (statement_date + 30 d) with reason "Payment due date printed on the statement"; clean true.
- duplicate / above_cash / unbundled: options dispute ("Send the dispute letter", "Letter cites the hospital's own price file row; hospital has 30 days to answer"), itemized ("Request the itemized bill first", "Delays payment; confirms each line before disputing"), drop ("Pay as billed", "You accept the charge"). Default: dispute for duplicate and above_cash; itemized for unbundled. Deadline = statement_date + 30 d (payment due) with reason "Payment is due on this date; a written dispute before it keeps the account out of collections". situation names the kind, the lines, the amount, and the file row (e.g. "Line 3 and line 4 bill CPT 85025 twice on 2026-08-14 at 84.00. The hospital's price file lists it once at 84.00 (row 13220)."). `needs_user_judgment` false.
- upcoded: options ask_provider ("Ask the hospital to justify the visit level", "Letter asks for the coding rationale against your visit summary"), itemized, drop. Default ask_provider. needs_user_judgment true; situation ends with "This needs your judgment: does the visit summary match what happened?".
- out_of_network: options dispute ("Send the No Surprises Act notice", "Cites 45 CFR 149.420; provider may bill only in-network cost sharing"), pay_in_network ("Pay only the in-network share", "Pay what the plan says you owe for in-network care; keep the letter on file"), drop. Default dispute. Deadline = today + 120 d, reason "CMS patient-provider dispute window: 120 calendar days from the bill date" (source: https://www.cms.gov/medical-bill-rights/help/dispute-a-bill, quoted in data/SOURCES.md). amount_at_stake from the finding; basis "gross".
- evidence_url: hospital's mrf_url from data/hospitals.json (or the transparency page for OU if in registry); evidence_lines: fixture source_line numbers from the evidence rows.
- Multiple findings on one bill: one card, the highest amount_at_stake finding leads; the others are listed in situation's second sentence.

### A3. Letters (`letters.py`): `draft_letter(bill, result, card, option_id, model=None) -> Letter`. One Strands Agent with `structured_output_model=Letter`, system prompt fixed, temperature 0. Inputs are the card and findings serialized; the prompt forbids inventing facts, amounts, dates, or rights not in the input. Citations are supplied by Python, not the model: 45 CFR 180.50 (hospital must publish standard charges, the file consulted, fetch date), the hospital's own row (code, description, cash or gross, source line, URL), 45 CFR 149.420 for out_of_network, and for itemized requests the plain request for an itemized statement. Post-check (deterministic): every amount and code in the body must appear in the inputs; every citation string in `citations` must appear in the body; else retry once with the same model, then fallback model (`make_model(fallback=True)`), else raise. Footer fixed: "Fairbill drafts letters from public price data. This is not legal advice. Patient names in this demo are fictional." Address: hospital billing address from the registry; from_name the bill's patient_name. `kind`: dispute for dispute/ask_provider, itemized_request for itemized, nsa_complaint for out_of_network dispute. Save a plain-text render at `_runs/<date>_letters/<bill_id>_<kind>.txt` only when the CLI asks.

### A4. Calendar (`decisions.py`): `calendar_ics(card: DecisionCard, bill: Bill) -> str` builds a valid VCALENDAR with one VEVENT (all-day) on card.deadline, SUMMARY "Fairbill: <bill_id> response deadline (<kind>)", DESCRIPTION the deadline_reason and evidence_url, UID deterministic. Validate with a line-length and CRLF check.

### A5. Ledger (`ledger.py`): JSON-lines file at `$FAIRBILL_LEDGER_DIR/<session_id>.jsonl` (default `_runs/ledger/`). API: `append(session_id, entry: LedgerEntry) -> LedgerEntry`, `list(session_id) -> list[LedgerEntry]`, `undo(session_id, entry_id) -> LedgerEntry` (marks undone, appends a reversal row with actor user; refuses if `undo` is None, i.e. reads), `veto_window_minutes = 10` for silent actions (`final_after`), reads and user-tapped decisions are final immediately. Every pipeline step writes a row: read (no undo), fetch (no undo), audit (no undo), decision (undo = "withdraw decision"), letter drafted (undo = "discard draft"), calendar entry (undo = "remove entry"), guard denial (actor guard, no undo).

### A6. Guard (`guard.py`): a Strands `InterventionHandler` (see ../03_HOOKS_PLUGINS_INTERVENTIONS.md; `on_error='deny'`) that denies any tool call whose tool name matches `pay|payment|charge_card|transfer|submit_payment|sign|send_email|autopay` or whose arguments (recursively, any key or string value) match card-number / bank / routing patterns (`\b\d{13,19}\b`, `routing`, `account_number` when paired with `pay`, `cvv`, `iban`). The Deny reason is written to the ledger (actor guard) and returned to the model as the tool result so the trace shows it. Provide `pay_bill(amount, method)` as a decoy `@tool` that would only return a string; it must never execute when the guard is installed (assert in tests). `chat(session_id, bill_id, text, card) -> str`: a small Strands Agent with tools [pay_bill, code_lookup] and the guard installed, system prompt "You help a patient understand this bill. You never move money." The demo utterance "just pay it" must produce a denied pay_bill call visible in the returned trace summary (list of tool calls with status). Also a PII redaction hook (`AfterToolCall` / message hook) that masks patient_name and account_number in any logged trace text (replace with "[patient]" / "[account]").

### A7. Live fetch (`fetch.py`): `fetch_price_file(hospital_id, timeout_s=20, max_bytes=None) -> FetchReport`. Streams GET on the registry mrf_url with a browser User-Agent, reports bytes and Content-Length, computes sha256 over what was received, stops at timeout or max_bytes. Norman (39 MB): download fully when under timeout, then verify that `MRF(path).lookup` on the downloaded file returns the same gross/cash for the gallery codes as the fixture (`matched_fixture`); lookups still use the fixture slice. OU (1.5 GB): fetch the first 8 MB only (`live_partial`), report total size, note "lookups use the committed slice (fetched 2026-09-13)". Any error or timeout -> status "fixture" with the error in note. Downloads go to `_runs/fetch_cache/` (gitignored), never to data/. Never block the pipeline more than timeout_s.

### A8. Pipeline (`decisions.py`): `async def run_pipeline(bill_id, session_id, today=None, live_fetch=True) -> AsyncIterator[dict]` yielding step events `{step: "read"|"fetch"|"audit"|"card"|"done", status: "start"|"ok"|"error", payload: ..., seconds}`. read: `reader.read_bill(gallery/bills/<bill_id>_photo.jpg)`; if the read differs from truth.json on any code or charge, still proceed but add a note (the demo shows what was read). fetch: A7. audit: `audit_async` (add it to audit.py: move the body of `audit()` into `async def audit_async(...)`, keep `audit()` as a sync wrapper; this is the one edit allowed in audit.py). card: A2. Every step writes a ledger row. Also `decide(session_id, bill_id, option_id) -> {letter, ics, ledger_entry}` and a results cache `gallery/results/<bill_id>.json` written by `python -m fairbill.decisions --precompute` (the full pipeline output for all six bills plus letters for the default option) used by the web tier when `?cached=1` or when a live step errors (the response says "cached" in that case).

CLI: `python -m fairbill.decisions --bill bill_02 [--no-fetch]` prints the steps, the card, the default letter, the ics, and the ledger; `python -m fairbill.decisions --guard-demo` runs A6's chat with "just pay it" and prints the denial; `--precompute` as above.

Done-check for A: `python -m fairbill.decisions --bill bill_02` shows a card with three options and default "dispute", a letter that cites row 14756 and 45 CFR 180.50, an ics with the 2026-09-11 deadline; `--bill bill_06` shows a clean card with one option and no letter; `--bill bill_05` letter cites 45 CFR 149.420; `--guard-demo` prints one denied pay_bill call; `--precompute` writes six result files.

## B. Web tier `src/fairbill/app.py` + `web/index.html` (+ `web/app.js`, `web/style.css`)

FastAPI app, phone-first single page, no build step, no external CDN (must load on cellular in under 2 s before results). Endpoints:
- `GET /` serves web/index.html; `GET /static/*` serves web/; `GET /gallery/<file>` serves gallery/bills/ (photos, page PNGs, PDFs).
- `GET /api/bills` -> `[{id, hospital_name, visit_type, service_date, photo_url, planted_kind_hidden: false}]` (do not reveal planted kinds in the list; the judge should discover them).
- `POST /api/run/{bill_id}` (query `cached=1` optional) -> SSE stream of A8 events. Session id from header `X-Fairbill-Session` (client generates a UUID, stores in localStorage).
- `POST /api/decide/{bill_id}` body `{option_id}` -> `{letter, ics_url, ledger_entry}`; `GET /api/ics/{bill_id}` -> text/calendar download.
- `POST /api/undo/{entry_id}`; `GET /api/ledger`.
- `POST /api/chat/{bill_id}` body `{text}` -> `{reply, tool_calls:[{name, status: "denied"|"ok", reason}]}` (A6).
- `GET /api/bench` -> the latest `_runs/2026-09-13_phase4_audit/bench.json` summary and `_runs/2026-09-13_phase3_reader/bench.json` summary.
- Mode switch: if env `FAIRBILL_RUNTIME_ARN` is set, `/api/run`, `/api/decide`, `/api/chat`, `/api/undo` proxy to AgentCore Runtime via boto3 `invoke_agent_runtime` (payload `{action, bill_id, session_id, ...}`; streaming responses relayed as SSE; `runtimeSessionId` = the client session id padded to 33+ chars). Otherwise call the core in-process. Same JSON either way.

Page (scenes 2 to 9 of PLAN.md, in order, one screen each, swipe/scroll):
1. Gallery grid: six photo thumbnails with hospital and visit type; a banner "Demo statements. Patients fictional; prices are the hospitals' own published standard charges (fetched 2026-09-13)."
2. Read: the photo on top; fields fill in as the SSE read step lands; each line row shows code, description, charge, price; tapping a line highlights its crop box on the page PNG (crops from truth.json served via `/api/bills/{id}/truth-crops`; only boxes, never the planted findings).
3. Fetch: hospital name, the real URL, progress bar with bytes / total, sha256 prefix, "live" or "fixture" badge with the note.
4. Audit: line rows turn green or red; a red row expands to bill value vs file value with the file row (source line, description, URL link). Clean bill: one green banner "Matches the hospital's file. Nothing to do."
5. Decision Card: situation, options as large tap targets, default marked, deadline, evidence link. Tap -> step 6.
6. Output: the letter (monospace, copy button), "Add deadline to calendar" (ics link), the ledger row appended.
7. Ledger drawer (bottom sheet): all rows with undo buttons.
8. Guard: a text box prefilled "just pay it" with a Send button; the reply and the denied tool call rendered as a trace card (tool name, DENIED, reason).
9. Bench footer: reader 6/6, audit 5/5, 0 false flags, from `/api/bench`, plus a link to the README.

Design: load `~/.claude/frontend-design-preset.md` first (the kernel requires it), then pick one direction and state it in the report; system font stack, dark-on-light, a single accent for "red" findings and one for "green"; 16 px side gutters; works at 390 px width; no framework. Fictional label visible on every screen (footer).

Run: `PYTHONPATH=src uvicorn fairbill.app:app --host 0.0.0.0 --port 8081`. Done-check for B: Playwright or a headless Chromium screenshot at 390x844 of each of the nine screens for bill_02 saved to `_runs/2026-09-13_phase5_web/screens/`, plus curl transcripts of every endpoint. If Playwright is missing, `pip install playwright && playwright install chromium` is allowed.

## C. Runtime entrypoint `src/fairbill/runtime.py` (Phase 6 uses it; build the file now)
`BedrockAgentCoreApp`, `@app.entrypoint async def invoke(payload, context)`: payload `{action: "run"|"decide"|"chat"|"undo"|"ledger"|"bills", bill_id?, option_id?, text?, entry_id?, cached?}`; `session_id = context.session_id`. `run` is an async generator yielding the A8 events (Runtime streams them as SSE); the others return JSON. Reject non-dict payloads and unknown actions with `{error}`. Port 8080 default from the SDK. Also `requirements.txt` at repo root listing runtime deps with pins (strands-agents, bedrock-agentcore, pydantic, opencv-python-headless, pymupdf, numpy, pillow, reportlab, fastapi, uvicorn, boto3, python-dotenv, strands-agents-tools), and `.dockerignore` excluding data/raw, _runs, .env, web screenshots.

## D. Evals `evals/` (Strands Evals, ../09_EVALS_SDK.md)
`evals/cases.py` builds one `Case` per gallery bill from truth.json; `evals/run_bench.py` runs the audit (from truth Bill objects, and separately end to end from photos) with deterministic evaluators (planted kinds and line_nos matched; zero findings on the clean bill; every finding cites a FileRow with a source_line except out_of_network) and an LLM-judge evaluator on the drafted default letter (rubric: cites the file row and regulation, no invented amounts, plain language, under 350 words; score 0..1, pass at 0.8) and writes `evals/report.json` and a markdown table `evals/BENCH.md` (columns: bill, planted, found, matched, false flags, letter score, reader exact, seconds). `strands-evals` CLI usage is optional; a Python runner is fine. Done-check: `PYTHONPATH=src python evals/run_bench.py` prints the table with 5/5, 0 false flags, reader 6/6, and letter scores.

## Non-negotiables
No payment fields anywhere in the UI. Fictional label on every screen and every letter. No AI attribution. Nothing outside the named file scopes. Real Bedrock calls are fine. Keep code minimal and readable.
